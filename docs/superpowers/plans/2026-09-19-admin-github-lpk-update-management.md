# 管理员 GitHub LPK 自动更新管理计划

已确认规格：[GitHub LPK 自动更新检查](../specs/2026-07-28-github-lpk-auto-update-design.md)

## 目标

修复管理员管理其他用户应用时看不到 GitHub 自动更新入口的问题，并在管理员应用列表增加多选批量启用操作。保持现有 Ent 策略表、逐应用 PATCH 接口和权限边界，不新增数据库字段或依赖。

## 实施顺序

1. 扩展版本解析：保留严格 SemVer，并支持至少三段的纯数字点分版本及逐段数值比较。
2. 调整应用详情 DTO：所有者和管理员始终获得默认或已保存的策略；资格校验仍在启用请求中执行。
3. 增加回归测试：管理员可查看其他用户不合格应用的策略入口，四段时间版本可启用，协作者权限不扩大。
4. 在管理员应用管理列表复用现有选择框、确认弹窗和逐应用 PATCH 接口实现批量启用；弹窗提供 1 到 720 小时的统一检查间隔，默认 24 小时。
5. 增加中英文结果文案和前端契约测试，构建并同步 `clientembed/dist`。

## 验收

- 管理员打开任何其他用户应用的管理页都能看到 GitHub 自动更新设置。
- `v2026.09.18.1622` 这类 GitHub Release tag 和对应版本可启用并正确比较。
- 不符合 GitHub Release LPK 条件的应用仍不能启用，并显示现有后端错误。
- 管理员可多选当前管理列表中的应用并确认批量启用；部分失败时其余应用继续处理并显示汇总。
- 应用所有者保留单应用设置，协作者仍不能修改策略。
- Go 定向测试、前端契约测试和生产构建通过。
- 服务端 patch 版本升级为 `0.1.52`，提交、推送 `main` 并发布 `server-v0.1.52`。
